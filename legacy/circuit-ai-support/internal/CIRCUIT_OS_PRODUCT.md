# CIRCUIT OS — Producto interno reservado

## Posición

CIRCUIT OS es la infraestructura que CIRCUIT utiliza para vender y entregar una sola cosa: modernización de circuitos de trabajo. No se comunica como SaaS público en la primera etapa. El cliente compra diagnóstico, decisión, implementación y mejora; CIRCUIT OS hace posible que el servicio sea repetible, medible y trazable.

## Módulos

| Módulo | Función interna | Salida para cliente |
|---|---|---|
| Intake / CRM | Capturar y ordenar oportunidad | Resumen de necesidad |
| Audit | Estructurar diagnóstico | Mapa actual y fricciones |
| Mapper | Comparar antes y después | Diagrama de circuito |
| Score | Evaluar dimensiones operativas | Score orientativo con explicación |
| Architect | Proponer opciones y riesgos | Arquitectura recomendada |
| Proposal | Preparar alcance y supuestos | Propuesta clara |
| Builder | Gestionar implementación | Roadmap y responsables |
| Monitor | Medir el circuito implantado | Revisión y mejora |
| Knowledge | Versionar fuentes y respuestas | Respuestas consistentes |
| Ledger | Registrar decisiones y errores | Evidencia y trazabilidad |

## Estado de una oportunidad

`NEW → QUALIFIED → DISCOVERY → DIAGNOSIS → PROPOSAL → IMPLEMENTATION → CARE → CLOSED`.

Ningún módulo puede saltar estado sin una transición válida, un responsable y una próxima acción. Un estado bloqueado debe poder explicar el motivo con un código Max Protocol.

## Regla de visibilidad

La web pública muestra método, resultados, casos simulados y criterio. La arquitectura de CIRCUIT OS, sus colas, reglas, prompts, matrices y paneles se mantiene interna salvo que un cliente necesite una parte documentada para operar su propio circuito.

## Regla de producto

Cada automatización interna debe ahorrar trabajo sin ocultar responsabilidad. Si no mejora una métrica o no reduce una fricción identificable, no entra en CIRCUIT OS.
